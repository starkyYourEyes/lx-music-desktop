# GitHub 最新音源导入设计

## 目标

在“设置 > 自定义源管理”中增加 GitHub 仓库连接测试和最新音源导入功能。应用从 `Macrohard0001/lx-ikun-music-sources` 的 `main` 分支识别最新版本目录，下载该目录内的全部 JavaScript 音源，并用这一批音源替换本地全部自定义源。

当前仓库最新目录为 `v260724`。该目录包含 3 个分类和 26 个 `.js` 文件：

- `V260720-其他`：12 个
- `V260720-推荐`：10 个
- `online`：4 个

导入范围包含 `online`。后续仓库增加更高版本的 `v/V + 6 位日期` 目录后，应用应自动选择新目录；仓库在同一版本目录内更新文件时，应用也应从最新提交重新导入。

## 已确认行为

- 设置页提供“测试仓库连接”和“获取最新音源”两个按钮。
- 连接测试只读取仓库提交和目录树，不下载脚本，也不修改本地数据。
- 获取操作导入最新版本目录内的全部 `.js` 文件，包括 `online`。
- 获取操作替换本地全部自定义源，包括用户从本地文件或其他网址导入的源。
- 应用在替换前显示确认框，列出本地源数量、远程版本和远程文件数量。
- 应用按最新版本目录下的第一级文件夹分组，并允许用户展开或折叠各组。
- 任一下载、校验、压缩或持久化步骤失败时，应用保留替换前的完整数据。
- 应用成功替换后只写盘一次，并只发送一次 `user_api_changed` 事件。

## 非目标

- 不支持用户配置其他 GitHub 仓库、分支或访问令牌。
- 不做定时后台更新，也不在启动时自动替换音源。
- 不比较脚本功能、可用音质或远程服务健康状态。
- 不执行导入脚本来验证其业务接口。现有自定义源运行环境继续负责脚本执行。
- 不提供单文件勾选、增量合并或冲突解决界面。

## 架构

渲染进程负责 GitHub 网络访问和界面状态，主进程负责脚本校验、压缩、运行环境切换和持久化。

这一边界复用 `src/renderer/utils/request.js` 中的代理和网络错误处理。主进程继续作为 `STORE_NAMES.USER_API` 的唯一写入者。渲染进程下载完完整快照后，通过一个批量 IPC 请求提交脚本文本及远程元数据。

```text
用户点击连接测试
-> 渲染进程读取 main 分支信息
-> 渲染进程读取该提交的递归目录树
-> 解析最新版本和 JS 清单
-> 显示版本、数量、短提交号

用户点击获取最新音源
-> 解析远程快照
-> 显示全量替换确认框
-> 按固定提交 SHA 下载全部脚本
-> 向主进程发送一个批量替换 IPC
-> 主进程解析并压缩全部脚本
-> 主进程一次性写入 user_api.json
-> 主进程切换内存数据并刷新当前源运行环境
-> 发送一次 user_api_changed
-> 渲染进程刷新分组列表并显示结果
```

## GitHub 快照发现

远程帮助模块使用以下固定配置：

```text
owner: Macrohard0001
repo: lx-ikun-music-sources
branch: main
```

模块先请求：

```text
GET https://api.github.com/repos/Macrohard0001/lx-ikun-music-sources/branches/main
```

响应中的 `commit.sha` 作为本次操作的固定提交。模块随后请求：

```text
GET https://api.github.com/repos/Macrohard0001/lx-ikun-music-sources/git/trees/{commitSha}?recursive=1
```

解析规则：

1. 接受根目录中名称匹配 `/^[vV](\d{6})$/` 的 `tree` 项。
2. 比较捕获到的六位数字，选择数值最大的目录。
3. 选择该目录下所有以 `.js` 结尾的 `blob` 项，扩展名比较忽略大小写。
4. 使用版本目录后的第一个路径段作为分组名。直接位于版本目录下的脚本归入版本名分组。
5. 保存完整仓库路径、blob SHA、文件大小、版本和分组。
6. 拒绝 `truncated: true`、无版本目录、无 JS 文件或字段类型不符的目录树。

脚本下载地址绑定同一个提交 SHA：

```text
https://raw.githubusercontent.com/Macrohard0001/lx-ikun-music-sources/{commitSha}/{encodedPath}
```

模块逐段编码路径，保留 `/` 分隔符。固定 SHA 防止下载期间 `main` 更新后出现跨提交文件组合。

## 下载与资源限制

下载器最多同时请求 4 个脚本。每个响应必须返回 HTTP 200 和字符串正文。

资源限制：

- 单文件上限：9,000,000 字节，与现有在线导入限制一致
- 文件数量上限：200 个
- 所有脚本正文总上限：50,000,000 字节

目录树中的 `size` 用于下载前检查，下载后的 UTF-8 字节数用于最终检查。任一文件超过限制时，下载器停止整批操作。

GitHub API 未认证请求可能触发限流。帮助模块读取响应状态和 `x-ratelimit-reset`，将限流错误转换为可显示的信息。连接测试和获取操作都通过应用现有代理设置访问网络。

## 批量替换与数据模型

`LX.UserApi.UserApiInfoFull` 和 `LX.UserApi.UserApiInfo` 增加可选远程字段：

```ts
remote?: {
  provider: 'github'
  repository: 'Macrohard0001/lx-ikun-music-sources'
  version: string
  group: string
  path: string
  blobSha: string
  commitSha: string
}
```

本地和在线单文件导入不设置 `remote`。界面将这类源放入“本地导入”组。

批量 IPC 接收下载完成的脚本清单。主进程按以下顺序处理：

1. 校验批量参数、远程字段和资源限制。
2. 对每个脚本调用现有脚本头部解析逻辑。
3. 根据规范化仓库路径计算稳定 ID，例如 `user_api_github_` 加路径 SHA-256 的前 16 位。
4. 压缩所有脚本，构建新的信息数组和脚本 Map。
5. 将序列化后的完整数组写入 `STORE_NAMES.USER_API`。
6. 写入成功后替换内存中的 `userApis` 和 `scripts`。
7. 发送一次 `user_api_changed`。

主进程在步骤 5 前不修改现有数组或 Map。脚本解析和压缩失败不会改变旧数据。存储写入失败也不会切换内存状态。

稳定 ID 让同一路径的远程源在后续提交中保留身份。批量替换期间，主进程关闭当前自定义源运行窗口。新列表仍包含当前 ID 时，主进程用新脚本重新加载该 ID；路径已删除时，渲染进程将 `common.apiSource` 回退到现有可用内置源。

远程字段需要进入现有桌面自定义源同步数据和稳定 MD5。其他设备因此可以保留分类信息，并能识别只改动远程元数据的更新。

## 设置页界面

`UserApiModal.vue` 保留现有标题、脚本风险提示、在线导入和本地导入功能。

底部新增两个命令按钮：

- `测试仓库连接`
- `获取最新音源`

四个按钮在可用宽度内组成两组，窄窗口换行。请求执行期间，两个 GitHub 按钮进入禁用状态；当前按钮显示“测试中...”或“获取中...”。弹窗内显示最近一次操作状态。

连接成功状态包含远程版本、文件数量和提交 SHA 前 7 位。获取成功状态包含导入版本与数量。失败状态使用对话框显示错误，并在弹窗状态区域保留简短结果。

点击获取后先发现快照，再显示确认框：

```text
将清空现有 {localCount} 个自定义源，并导入 {version} 的 {remoteCount} 个音源。是否继续？
```

用户确认后才下载脚本。确认框不提供文件选择。

列表按 `remote.group` 分组。缺少远程字段的源归入“本地导入”。每个分组标题显示名称、数量和现有 `#icon-down` 图标；用户点击标题切换展开状态，图标随状态旋转。组件在本次打开期间保存折叠状态，关闭弹窗后重置。

远程批量导入包含 26 个源，因此移除 `UserApiModal.vue` 中只存在于界面的 20 个源限制。主进程使用脚本大小和批量总量限制保护存储与内存。

## 错误处理

界面向用户区分以下错误：

- 无法连接网络或请求超时
- GitHub API 限流
- GitHub 返回非 200 状态
- 分支提交或目录树格式错误
- 目录树被截断
- 找不到版本目录或 JS 文件
- 文件数量、单文件或总大小超过限制
- 指定路径下载失败
- 脚本缺少有效的自定义源头部
- 本地数据写入失败

错误信息可以包含失败文件的相对路径，但不显示完整脚本内容。应用不记录脚本文本。

批量替换采用全有或全无策略。一个无效脚本会取消整批导入，界面报告该文件，用户原有音源保持可用。

## 文案与可访问性

新增文案写入 `zh-cn.json`、`zh-tw.json` 和 `en-us.json`。分组标题使用可点击按钮，并提供展开状态对应的 `aria-expanded`。图标按钮和删除按钮保留可读的 `aria-label`。

按钮文字、状态和错误信息在窄窗口内换行或省略，不能覆盖相邻控件。颜色沿用主题变量，不引入新的固定色板。

## 测试计划

### 远程快照解析

- 从大小写混合的多个版本目录中选择数值最大的版本。
- 同一版本的新提交继续生成新的快照提交号。
- 只选择最新版本目录内的 `.js` blob。
- 保留 `V260720-其他`、`V260720-推荐` 和 `online` 三组。
- 忽略图片、README、URL 文件和版本目录外脚本。
- 拒绝截断目录树、空版本、无脚本、非法 SHA 和无效字段。
- 生成绑定提交 SHA 且正确编码中文路径的 raw URL。

### 下载

- 将并发请求数限制为 4。
- 接受 HTTP 200 的字符串正文。
- 拒绝非 200、超时、限流、超大单文件、过多文件和超大总正文。
- 任一文件失败时不调用批量替换 IPC。

### 主进程替换

- 为相同仓库路径生成相同 ID。
- 保存版本、分组、路径、blob SHA 和提交 SHA。
- 成功批量替换只写盘一次并发送一次变更事件。
- 当前 ID 保留时重新加载脚本，ID 消失时关闭旧运行环境。
- 任一脚本解析或压缩失败时保留旧数组、脚本 Map 和磁盘数据。
- 存储写入失败时保留旧内存数据。
- 同步数据包含远程字段，稳定 MD5 会响应远程字段变化。

### 设置页与回归

- 检查两个新增按钮、加载状态、确认框、状态信息和 IPC 调用。
- 检查分组数量、默认展开、折叠切换和无远程字段分组。
- 检查当前源不存在时回退到内置源。
- 运行现有 `scripts/test-user-api-sync.js` 和 `scripts/test-user-api-sync-v2-wiring.js`。
- 运行新增测试、TypeScript、相关 ESLint、`git diff --check` 和生产构建。
- 条件允许时启动 Electron 开发环境，检查弹窗在桌面和最小宽度下没有重叠或截断。

## 验收标准

1. 连接测试可报告当前 `v260724`、26 个 JS 文件和仓库提交号。
2. 获取操作导入全部 26 个源，并显示 3 个可折叠分类。
3. 仓库增加更高版本目录后，应用无需发版即可发现并导入新版本。
4. 仓库只更新当前版本内容时，应用仍从新提交重新导入。
5. 网络、下载、脚本或存储错误不会清空或部分覆盖旧源。
6. 更新后仍存在的当前源加载新脚本；已删除的当前源回退到内置源。
7. 本地导入、在线导入、删除、更新提醒和自定义源同步保持可用。
