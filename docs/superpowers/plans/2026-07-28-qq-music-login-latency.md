# QQ Music Login Latency Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the browser-backed QQ Music login QR as soon as the official frame renders it, normally within three seconds, while giving every attempt bounded cancellation, expiry, proxy, and cleanup behavior.

**Architecture:** Keep one isolated Electron OAuth browser per active attempt, but start QR discovery as soon as navigation starts instead of awaiting the whole document. The renderer owns a UUID request ID; the main-process login service registers that ID before its first await, applies one absolute 15-second creation deadline, and disposes pending or active work through a single lifecycle. Logical teardown destroys the window immediately, while isolated-partition clearing settles under a separate five-second budget.

**Tech Stack:** Electron 37, TypeScript 5.9, Vue 3 Composition API, Node 22 focused script tests, Web Performance API, ESLint, webpack.

---

## Global Constraints

- Execute in an isolated worktree created with `superpowers:using-git-worktrees`.
- Preserve the browser-backed QQ OAuth parent-page flow. Do not restore direct `ptqrshow`/`ptqrlogin` ownership in the application.
- Do not prewarm, persist, or reuse a QQ login `BrowserWindow`, partition, cookie jar, or QR between attempts.
- Keep `contextIsolation`, sandboxing, disabled Node integration, denied permissions, the navigation allowlist, blocked new windows/webviews, and cookie filtering.
- Accept only lowercase canonical UUID v4 request IDs generated by `crypto.randomUUID()`.
- Start the 15-second creation deadline in the main IPC handler before calling account or login services.
- Treat logical teardown and partition cleanup separately: entry removal, abort, and `BrowserWindow.destroy()` are synchronous; cache/storage clearing may continue for at most five seconds.
- Never log cookies, QR image data, OAuth codes, partition names, full URLs, query strings, or upstream response bodies.
- Do not change account persistence, QQ recommendation APIs, the two-second polling cadence, or the public `LX.QQMusic.LoginQr`/`LoginQrCheck` fields.

- [ ] **Step 4: Add one absolute abort/deadline primitive**

Replace `withTimeout` with an absolute-bound helper. Every asynchronous creation stage must use this helper or receive the same `deadlineAt`; no stage may add a fresh 15 seconds:

```ts
type CreateFailureReason = 'cancelled' | 'timed-out' | 'failed'

class QQMusicBrowserCreateError extends Error {
  constructor(readonly reason: CreateFailureReason) {
    super(CREATE_ERROR)
  }
}

const waitWithinCreation = async<Result>(
  promise: Promise<Result>,
  signal: AbortSignal,
  deadlineAt: number,
): Promise<Result> => {
  return new Promise<Result>((resolve, reject) => {
    let settled = false
    let timer: ReturnType<typeof setTimeout> | undefined

    const finish = (callback: () => void) => {
      if (settled) return
      settled = true
      if (timer) clearTimeout(timer)
      signal.removeEventListener('abort', handleAbort)
      callback()
    }
    const handleAbort = () => {
      finish(() => reject(new QQMusicBrowserCreateError('cancelled')))
    }
    const remainingMs = deadlineAt - Date.now()
    if (signal.aborted) {
      handleAbort()
      return
    }
    if (remainingMs <= 0) {
      finish(() => reject(new QQMusicBrowserCreateError('timed-out')))
      return
    }

    signal.addEventListener('abort', handleAbort, { once: true })
    timer = setTimeout(() => {
      finish(() => reject(new QQMusicBrowserCreateError('timed-out')))
    }, remainingMs)
    promise.then(
      value => {
        const reason = Date.now() >= deadlineAt ? 'timed-out' : null
        finish(() => {
          if (reason) reject(new QQMusicBrowserCreateError(reason))
          else resolve(value)
        })
      },
      error => {
        const timedOut = Date.now() >= deadlineAt
        finish(() => {
          if (timedOut) reject(new QQMusicBrowserCreateError('timed-out'))
          else reject(error)
        })
      },
    )
  })
}
```

Only cancellation and deadline expiry become `QQMusicBrowserCreateError`.
Ordinary Electron/frame rejections remain internal values: the QR discovery
loop catches them and retries, while the factory's outer catch converts any
eventual failure to the fixed public creation error without logging the
upstream object. The original promise always receives both fulfillment and
rejection handlers, so a late rejection cannot become unhandled.

Change `captureQrImage` to accept `signal`, `deadlineAt`, a terminal-state getter, and a diagnostic callback. Its loop must:

```ts
const captureQrImage = async({
  win,
  signal,
  deadlineAt,
  getTerminalReason,
  emit,
}: {
  win: Electron.BrowserWindow
  signal: AbortSignal
  deadlineAt: number
  getTerminalReason: () => QQMusicBrowserAuthTerminalReason | null
  emit: (stage: QQMusicBrowserAuthProgressStage) => void
}): Promise<string> => {
  let frameReported = false
  let imageReported = false

  while (Date.now() < deadlineAt) {
    const terminalReason = getTerminalReason()
    if (terminalReason) throw new QQMusicBrowserCreateError('failed')
    if (signal.aborted) throw new QQMusicBrowserCreateError('cancelled')
    if (win.isDestroyed()) throw new QQMusicBrowserCreateError('failed')

    const frame = findLoginFrame(win)
    if (frame) {
      if (!frameReported) {
        frameReported = true
        emit('login-frame-found')
      }
      try {
        const [iframeRect, imageInfo] = await waitWithinCreation(
          Promise.all([
            win.webContents.executeJavaScript(GET_IFRAME_RECT_SCRIPT) as Promise<RectLike | null>,
            frame.executeJavaScript(GET_QR_IMAGE_INFO_SCRIPT) as Promise<QrImageInfo | null>,
          ]),
          signal,
          deadlineAt,
        )
        if (iframeRect && imageInfo?.complete &&
          imageInfo.naturalWidth > 0 && imageInfo.naturalHeight > 0) {
          if (!imageReported) {
            imageReported = true
            emit('qr-image-ready')
          }
          const captureRect = getQQMusicQrCaptureRect(iframeRect, imageInfo)
          if (captureRect) {
            const image = await waitWithinCreation(
              win.webContents.capturePage(captureRect),
              signal,
              deadlineAt,
            )
            if (!image.isEmpty()) {
              emit('qr-captured')
              return image.toDataURL()
            }
          }
        }
      } catch (error) {
        if (error instanceof QQMusicBrowserCreateError) throw error
      }
    }

    await waitWithinCreation(delay(QR_DISCOVERY_INTERVAL_MS), signal, deadlineAt)
  }

  throw new QQMusicBrowserCreateError('timed-out')
}
```

```powershell
function Get-QQCpuPercent {
  $qqSamples = 1..5 | ForEach-Object {
    (Get-CimInstance Win32_PerfFormattedData_PerfOS_Processor -Filter "Name='_Total'").PercentProcessorTime
    Start-Sleep -Seconds 1
  }

function Invoke-QQTtfbProbe {
  param(
    [Parameter(Mandatory = $true)][string]$Url,
    [string]$ProxyUrl = ''
  )

  $qqCurlArgs = @(
    '--connect-timeout', '5',
    '--max-time', '15',
    '-L',
    '-o', 'NUL',
    '-sS',
    '-w', '%{time_starttransfer}'
  )
  if ($ProxyUrl) { $qqCurlArgs += @('--proxy', $ProxyUrl) }
  $qqCurlArgs += $Url
  $qqRawTtfb = & curl.exe @qqCurlArgs
  if ($LASTEXITCODE -ne 0) { throw "QQ reachability probe failed" }

  $qqTtfb = 0.0
  $qqParsed = [double]::TryParse(
    $qqRawTtfb,
    [Globalization.NumberStyles]::Float,
    [Globalization.CultureInfo]::InvariantCulture,
    [ref]$qqTtfb
  )
  if (-not $qqParsed -or $qqTtfb -le 0) {
    throw "QQ reachability probe returned an invalid TTFB"
  }
  return $qqTtfb
}
```

- [ ] A ready browser-generated QR can cross IPC while unrelated OAuth resources are still loading.
- [ ] One absolute deadline begins in the main IPC handler and covers replacement teardown, proxy setup, navigation, discovery, and capture.
- [ ] The isolated QQ partition awaits fixed/direct proxy configuration before navigation.
- [ ] Close, refresh, unmount, replacement, success, expiry, third transient failure, terminal browser failure, timeout, logout, and main-window close all dispose the correct request exactly once.
- [ ] Cancel-before-create reordering is covered by 30-second tombstones capped at 64.
- [ ] A late browser result or status check cannot reactivate or authenticate a cancelled request.
- [ ] The first two consecutive transient checks preserve the session; a success resets the count; the third failure returns normalized `expired`.
- [ ] Expected allowlisted `ERR_ABORTED` navigation is nonterminal and every `loadURL` rejection is observed.
- [ ] Logical window destruction is immediate; isolated storage cleanup settles or reports timeout within a separate five-second budget.
- [ ] The visible timing endpoint requires image load, non-zero natural dimensions, a rendered animation frame, DOM connection, visible style, and non-zero bounds.
- [ ] At least 9/10 direct and 9/10 healthy-proxy attempts are visible within three seconds under the documented preconditions.
- [ ] Public types, IPC, errors, and diagnostics expose no credentials or upstream-sensitive values.
